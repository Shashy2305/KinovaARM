# Test plan for the overnight work (2026-10-09)

Everything below was built with the arm in Dry Run and tested offline (unit tests, stub nodes, real camera frames, MoveIt IK/FK
only). Nothing here has moved the arm. Tomorrow's job is to verify each piece on the real arm, **in this order**, stopping at the first
surprise. Environment for tests and tools: `source /opt/ros/humble/setup.bash && source /mnt/ros_workspace/venv/bin/activate`
(ROS first, venv second), then `PYTHONPATH=$PYTHONPATH:src/thesis_robot python3 -m pytest -p no:anyio src/thesis_robot/test`.
For ROS tools: `source scripts/ros_env.sh`.

## What changed, and its switch

| Feature | Parameter (node) | Default | Where it acts |
|---|---|---|---|
| Plan verification + retry hint, grammar repair, memory block | `plan_verification`, `grammar_repair`, `planner_memory` (`/llm_planner`) | ON | planner only (arm unaffected) |
| Retry from a NEW closing angle | `grasp_retry_new_angle` (`/arm_controller`) | **ON** (second attempt only) | pick |
| Shape-ranked closing angle on EVERY attempt | `grasp_candidates` | OFF | pick |
| Bias that ranking by past outcomes | `grasp_policy` | OFF | pick |
| Preshape width from the measured shape | `use_shape_width` | OFF | pick |
| Angled approach | `approach_tilt_deg`, `retry_tilt_deg`, `tilt_azimuth_deg` | 0 / 0 / auto | pick |
| Unknown obstacles in the carry/sweep checks | `use_unknown_obstacles`, `unknown_obstacles_min_cameras` | OFF (always logged) | place, pick |
| Faster big free-space moves | `smooth_free_vel_scale` (0.30 = unchanged) | 0.30 | all moves |
| Minimum-jerk smoothing | `smooth_trajectories` | ON | all moves |
| Outcome log | `outcome_log` | ON | records only |

**IMPORTANT - Go Live restarts the controller and resets every `ros2 param set`.** Either (1) press Go Live FIRST and `ros2 param set` afterwards, or (2) edit
`config/arm_controller_params.yaml` / `config/llm_planner_params.yaml` (loaded on every start, including Go Live and Go Dry Run) and then restart. The shipped files equal
the defaults; a test keeps them in step with the code.
Rollback for anything: `ros2 param set /arm_controller <name> <old value>` (no restart), or restore the file value and restart (it returns to Dry Run).

## Stage 4 - live baseline (Go Live, the arm moves, 30 min)
Hands clear, E-stop reachable, objects >= 15 cm from each other and the base. Run, one at a time, with all new flags at their defaults:
the three relational commands, plus "pick up the X and put it aside" for each of the four objects.
Record with `python3 scripts/outcome_report.py --recent 10`. Pass: >= 90% of commands complete; every failure has a clear refusal reason.

Training data builds up during this stage: every live pick saves the wrist frame before the descent and keeps it only if the pick ended with the
object held (`~/.ros/training_data/samples`, correct label from the command). After the stages: `python3 scripts/export_training_dataset.py` (counts per class,
how many masks are 'auto-mask'); fine-tune the detector once each class has a few dozen samples (command printed in the script's header).

## Stage 5 result, run live 2026-10-09 21:02-21:07 (`low_pick_tip_clearance_m` 0.06 for the test, restored to 0.03 each time)
PASS. Attempt 1 gripped at rho 90 deg (shape width 62 mm = table value) and closed on air (finger 0.693) as intended; attempt 2 logged `closing direction 150 deg ... (already tried: [90])`, turned +30 deg and
used rho 138 deg (48 deg away, 96 mm across). Both attempts failed on purpose (the raised clearance applied to the retry too), nothing was touched or dropped.
Finding from the first run: the retry stopped with "the wrist camera cannot see the mouse". The segmentation model is orientation-sensitive: a mouse lying ACROSS the wrist image was not detected at all
(best guess "traffic light" 0.08) but reads "mouse" 0.94 with the image turned 90 deg. `wrist_detection` now looks again with the image rotated 90 deg when nothing confident was found
(`rotated_fallback`, default True; detections carry `via_rotation`); verified on the live frame and in the second run. The same sensitivity probably affects the RealSense detectors for objects seen from the side.

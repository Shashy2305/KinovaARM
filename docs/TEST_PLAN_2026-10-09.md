# Test plan for the overnight work (2026-10-09)

Everything below was built with the arm in Dry Run and tested offline (unit tests, stub nodes, real camera frames, MoveIt IK/FK
only). Nothing here has moved the arm. Tomorrow's job is to verify each piece on the real arm, **in this order**, stopping at the first
surprise. Environment for tests and tools: `source /opt/ros/humble/setup.bash && source /mnt/ros_workspace/venv/bin/activate`
(ROS first, venv second), then `PYTHONPATH=$PYTHONPATH:src/thesis_robot python3 -m pytest -p no:anyio src/thesis_robot/test`.
For ROS tools: `source scripts/ros_env.sh`.

## What changed, and its switch

| Feature | Parameter (node) | Default | Where it acts |
|---|---|---|---|
| Plan verification + retry hint, grammar repair, memory block | `plan_verification`, `grammar_repair`, `planner_memory` (`/llm_planner`) | ON | planner only (arm unaffected) |
| Retry from a NEW closing angle | `grasp_retry_new_angle` (`/arm_controller`) | **ON** (second attempt only) | pick |
| Shape-ranked closing angle on EVERY attempt | `grasp_candidates` | OFF | pick |
| Bias that ranking by past outcomes | `grasp_policy` | OFF | pick |
| Preshape width from the measured shape | `use_shape_width` | OFF | pick |
| Unknown obstacles in the carry/sweep checks | `use_unknown_obstacles`, `unknown_obstacles_min_cameras` | OFF (always logged) | place, pick |
| Faster big free-space moves | `smooth_free_vel_scale` (0.30 = unchanged) | 0.30 | all moves |
| Minimum-jerk smoothing | `smooth_trajectories` | ON | all moves |
| Outcome log | `outcome_log` | ON | records only |

Rollback for anything: `ros2 param set /arm_controller <name> <old value>` (no restart), or restart the node (it returns to Dry Run).

## Stage 0 - preflight (Dry Run, 10 min)
1. Dashboard: robot bringup up, cameras `ok` (RS1, RS2, wrist; OAK-D off), arm `READY [DRY RUN]`. `scripts/check_system.sh` passes.
2. `/fault_controller/internal_fault` is `false`: `ros2 topic echo /fault_controller/internal_fault --once`.
3. Ollama warm: `ollama ps` shows `qwen2.5:7b` (the planner keeps it loaded 6 h; a cold load took 78 s).
4. `git log -1` is the last commit of 2026-10-09; unit tests pass (>= 261).
5. Table clear of foreign objects (the other lab user leaves ArUco sheets and boards on it; they are < 3 cm and ignored by the guard).

## Stage 1 - planner benchmark (Dry Run, no arm, 15 min)
`python3 scripts/planner_benchmark.py --reps 5 --label morning` (refuses to run unless the arm is in Dry Run).
Pass: >= 95% structurally correct, and `repaired` 0 or rare (repairs mean the model failed 3 times; look at those commands).
Baseline before the work: 84% (27/32). Overnight: 50/50. Compare `ros2 param set /llm_planner planner_memory false` to see what memory adds.

## Stage 2 - shape analysis (Dry Run, live wrist camera, 15 min)
Put the mouse (62 x 105 mm), the cup and the bottle under the wrist camera one at a time (arm hovering above, Dry Run: hand-guide
only if you are comfortable; otherwise use the saved frames). Read `det['shape']` on `/wrist_pixel_detections`.
Pass: mouse width across the short axis within +-8 mm of 62; `shape` is `elongated`; long axis within 8 deg of the real one; the cup with handle shows a `handle`.
The widths need the camera's height above the object (the controller computes it from TF); the logged `shape` event also carries `width_mm` vs `table_width_mm`.

## Stage 3 - obstacle guard (Dry Run, 15 min)
`ros2 topic echo /unknown_obstacles` (JSON). Place an object the detectors do not know (a stapler, a box, your hand).
Pass: it appears within 5 cm of its real position as `confirmed: true` within ~3 s; the four known objects do NOT appear; over 5 minutes of an
empty table + the 4 objects there are no `confirmed` phantoms. Known tentative blobs (one camera) near the open gripper are expected and ignored.
CPU of the node must stay < 20% (`top`).

## Stage 4 - live baseline (Go Live, the arm moves, 30 min)
Hands clear, E-stop reachable, objects >= 15 cm from each other and the base. Run, one at a time, with all new flags at their defaults:
the three relational commands, plus "pick up the X and put it aside" for each of the four objects.
Record with `python3 scripts/outcome_report.py --recent 10`. Pass: >= 90% of commands complete; every failure has a clear refusal reason.
This is the reference the later stages are compared with.

## Stage 5 - retry from a new angle (Go Live, 20 min)
Needs a first attempt that fails. Use a smooth object (the steel flask was unliftable) or temporarily `ros2 param set /arm_controller low_pick_tip_clearance_m 0.06`
for the mouse (the first close lands above it), then restore 0.03 immediately after.
Pass: the log shows `align: closing direction ... (already tried: [...])` on attempt 2 with a direction >= 30 deg from the first; the outcome log's second
pick record has a different `rho`; nothing collides. If attempt 2 repeats the first angle, report it (`events: grasp_candidates` shows why).

## Stage 6 - shape-ranked angles on every attempt (Go Live, 20 min)
`ros2 param set /arm_controller grasp_candidates true`. Run the same mouse/cup picks as stage 4.
Pass: success rate not worse than stage 4; the chosen turn for the mouse is the short-axis turn (+-15 deg). `grasp_candidates` events list the top 3.
Roll back to false if any pick is worse.

## Stage 7 - speed and the learned policy
a) `ros2 param set /arm_controller smooth_free_vel_scale 0.45`: hover/carry swings run faster. Compare mean pick seconds (stage 4: 23.9 s) from the outcome log.
Pass: faster with no jolt (peak speed 0.45 x joint limit ~ 0.63 rad/s); if it looks too fast, 0.38.
b) After >= 10 live picks with `shape` events: `python3 scripts/outcome_report.py` prints grasp lessons ("Gripping the mouse across its short side has worked n/n").
Then `ros2 param set /arm_controller grasp_policy true` together with `grasp_candidates true`.

## Stage 8 - unknown obstacles in the checks (Go Live, 20 min)
Confirm stage 3 first. `ros2 param set /arm_controller use_unknown_obstacles true`. Put a box (> 10 cm tall) on the straight carry path of "pick up the cup and put it
next to the bowl". Pass: the carry routes around it (`routing the carry around the unknown object`) or refuses with the reason, never through it.
A hand reaching in must also stop motion (check: it appears as `confirmed`). Then `false` again unless you want it on permanently.

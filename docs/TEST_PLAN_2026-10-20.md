# What is waiting for the arm (written 2026-10-20 evening, nothing below has moved the arm yet)
Same rules as docs/TEST_PLAN_2026-10-09.md: Dry Run until you say go, E-stop in hand, hands off the arm, `go home` first, one change at a time, `ros2 param set` is lost at every Go Live (set after going live, or edit `config/arm_controller_params.yaml`).
Start: `source scripts/ros_env.sh && python3 scripts/preflight.py` (RS3 detection/TF stay stopped, that is expected).

## A. Jerk-limited S-curve (new, default off) - the biggest speed win measured
1. Go Live, `go home`. Run 3 picks at defaults (note the seconds in `python3 scripts/outcome_report.py --recent 5`).
2. `ros2 param set /arm_controller smooth_profile s_curve` and repeat the same 3 picks. Expect hover transits about 35-40% shorter and a clean start/stop. Log lines say `(spline, s_curve)`.
3. If it looks harsh: `ros2 param set /arm_controller smooth_jerk_limit 4.0`; if it is smooth, only then consider `smooth_free_vel_scale 0.38`.
Pass: faster picks, no jolt, no new refusals. Rollback: `smooth_profile min_jerk`.

## B. Angled approach again (it worked on 2026-10-09: mouse 10 deg 4/4, cup 15-30 deg)
Things that were not tried: azimuth 180 (toward the base), a tall neighbour beside the gripper (the wrist-flip swing check), 5+ leaning picks in a row, the cup with the S-curve on.
Order: `approach_tilt_deg 15`, `tilt_azimuth_deg -1` (automatic) on the cup next to the mouse, then azimuth 180 explicitly, then a bottle as the neighbour. Always `go home` between sessions (a parked arm near the base broke the 20 deg lean's IK).

## C. 3D Fusion tab (new, no arm needed)
Open the 3D Fusion tab, press "By camera": RS1 red, RS2 green, white where they agree. The footer lists the median distance between each pair of cameras (RS1/RS2 measured 3.1 cm on 2026-10-20; aim for 1.5 cm). RS3 shows "no calibration (TF)" until it is calibrated.

## D. RealSense 3 calibration (blocked on a good pose)
See RUNBOOK 21b. Do 3-4 DIFFERENT arm poses in "Calibrate from arm" (Add this pose / Solve all poses; the arm may be hand-guided while Dry Run), save the candidate, then I run `calibration/check_markers.py` (ArUco board, DICT_4X4_50, ids 0-3, flat on the table in view of all three cameras)
and `refine_from_clouds.py` as a cross-check before `cp` to `~/.ros/realsense3_calibration.yaml`. Do not start RS3 detection before the markers agree within 3 cm: a mouse came out 16 cm below the table with the trial pose.
